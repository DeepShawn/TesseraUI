# v0.4.0：测试体系

预计 2～3 周。目标：首批 22 个组件在四端都达到设计规范第 8 节的“组件完成标准”。

## 1. 截图测试

- [x] Apple：改用 ImageRenderer（不增加依赖），macOS 上三种外观 × 浅色 / 深色 / 增强对比度配色共 9 张，CI 上传 `apple-snapshots`。限制：系统原生控件画不出来；增强对比度的描边需真机检查。iOS 一组移到 v0.5
- [ ] Windows：WinAppDriver（或 Windows App SDK 的 UI 测试）截图，三种外观 × 浅色 / 深色 / 高对比度
- [x] Android：在现有 36 张基础上增加增强对比度（再加 18 张），共 54 张
- [x] Web：交互测试已每项截图；新增视觉对比 `test:visual`（比对计算样式而不是像素，避免各机器中文字体差异造成误报）
- [ ] CI 中三端截图测试失败时上传差异图

## 2. 无障碍自动化

- [x] Web：axe-core 扫描三种外观下的首页与组件总览，零严重问题（36 个组合）
- [x] Android：无障碍检查（Robolectric，读屏名称、触摸目标；对比度由令牌对比度检查覆盖）。发现并修复文本框没有读屏名称
- [ ] Apple：XCUITest 检查读屏标签、特征（traits）与焦点顺序
- [ ] Windows：Accessibility Insights 自动检查
- [x] 增强对比度下三种外观都有可辨的边界（检查描边是否加回）：原生三端此前漏加，已修复

## 3. 中文输入法

- [ ] 制定输入法测试清单：拼音（全拼、双拼）、手写、九宫格、五笔；组合输入中不触发搜索 / 校验 / 字数统计，回车不提交
- [ ] 三端真机逐项测试并记录结果
- [x] Web：在交互测试中用 CDP 模拟组合输入（compositionstart / update / end）

## 4. 从 v0.3.2 移来

- [ ] 真机验证（iPhone、Android 中端 / 旗舰、Windows 笔记本）：流韵动效流畅度、触感、设备门槛；三端中文输入法下的焦点与光晕
- [x] Windows 流韵：开关滑块水滴形变、按压时圆角变成胶囊、菜单浮现（不做模糊：需要 Win2D，改为由淡到实、轻微放大上浮）
